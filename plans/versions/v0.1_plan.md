# V0.1 System Design: Journey Progress Social App

## Technology Stack

### Frontend (React Native)

- **Framework**: React Native 0.72+ with TypeScript
- **State Management**: Redux Toolkit + RTK Query
- **Real-time**: Socket.io-client
- **Authentication**: JWT with refresh tokens
- **Push Notifications**: @react-native-firebase/messaging

### Microservices Architecture

- **Runtime**: Node.js 18+ with TypeScript
- **Framework**: Express.js with Helmet, CORS
- **Database**: Cloud SQL PostgreSQL per service
- **Caching**: Cloud Memorystore Redis
- **Real-time**: Socket.io
- **Media Storage**: Cloud Storage + Cloud CDN
- **Authentication**: JWT + Refresh Token strategy
- **Email**: SendGrid
- **Containerization**: Docker containers

### Infrastructure (GCP + Pulumi IaC)

- **Compute**: Google Cloud Run (serverless containers)
- **Database**: Cloud SQL PostgreSQL (per service)
- **Cache**: Cloud Memorystore Redis
- **Storage**: Cloud Storage + Cloud CDN
- **Networking**: Cloud Load Balancer + VPC
- **Monitoring**: Cloud Monitoring + Cloud Logging + Sentry
- **CI/CD**: Cloud Build + GitHub Actions
- **IaC**: Pulumi for infrastructure management
- **Service Discovery**: Cloud Run service-to-service communication

## Microservices Architecture

### Service Overview

#### 1. Auth Service

**Responsibility**: User authentication, authorization, and session management
**Database**: auth_db (users, refresh_tokens, sessions)
**Key Entities**: User credentials, JWT tokens, OAuth integrations

#### 2. Profile/Journey Service

**Responsibility**: User profiles, goal management, and goal-related data
**Database**: profile_db (users, journeys, user_settings, categories)
**Key Entities**: User profiles, journeys, journey categories, privacy settings

#### 3. Feed Service

**Responsibility**: Feed generation, recommendations, and content discovery
**Database**: feed_db (feed_cache, user_follows, trending_data)
**Key Entities**: Feed algorithms, user relationships, content recommendations

#### 4. Post/Inspiration Service

**Responsibility**: Content creation, social interactions, and inspiration chains
**Database**: content_db (posts, inspirations, likes, comments, media)
**Key Entities**: Posts, inspiration chains, social interactions, media files

## Microservice Architecture (Based on Existing Boilerplate)

### Service Structure Pattern

Each microservice follows the existing boilerplate pattern:

```
service-name/
├── src/
│   ├── api/
│   │   └── feature/
│   │       ├── Feature.handler.mts    # Request handling logic
│   │       ├── Feature.routes.mts     # Route definitions
│   │       └── Feature.service.mts    # Business logic
│   ├── configs/
│   │   └── app.config.mts            # Service configuration
│   └── index.mts                     # Service entry point
├── package.json                      # Dependencies & scripts
└── ecosystem.config.cjs             # PM2 configuration
```

```yaml
# cloudbuild.yaml
steps:
  - name: 'gcr.io/cloud-builders/docker'
```

## Security Architecture

### Service-to-Service Security

- **JWT Tokens**: Service authentication with short-lived tokens
- **Network Security**: VPC private networking between services
- **IAM Roles**: Principle of least privilege for service accounts
- **API Rate Limiting**: Per-service request throttling
- **HTTPS Only**: TLS encryption for all communications

### Data Protection

- **Database Security**: Cloud SQL with encrypted connections
- **Input Validation**: Request validation at API gateway level
- **Secret Management**: Google Secret Manager for credentials
- **Access Controls**: Role-based access control (RBAC)
- **Audit Logging**: Cloud Audit Logs for security monitoring

## Scalability & Performance

### Microservices Scaling

- **Auto-scaling**: Cloud Run automatic scaling based on CPU/memory
- **Load Distribution**: Cloud Load Balancer across service instances
- **Database Scaling**: Cloud SQL read replicas for read-heavy operations
- **Caching Strategy**: Redis for frequently accessed data (feeds, user sessions)

### Performance Optimization

- **CDN**: Cloud CDN for global media delivery
- **Database Indexing**: Optimized indexes for common query patterns
- **Connection Pooling**: Efficient database connection management
- **Async Processing**: Cloud Pub/Sub for non-blocking operations
